# Values the XSL-FO specification leaves to the processor

Both processors follow the specification; where it leaves a value open, they chose differently. A template that never sets these
values will look different. Make them explicit.

| What | Apache FOP 2.x | Facturely | Make it explicit |
|---|---|---|---|
| Default font size when none is set | 12 pt | 10 pt | `font-size="12pt"` on `fo:root` (inherits everywhere) to keep FOP's size. |
| Page size when `page-width` / `page-height` are missing | 8.26 × 11 in | A4 (210 × 297 mm) | `page-width="8.26in" page-height="11in"` on each `fo:simple-page-master` without a size (or the size the user really wants). |
| `border-width` keywords | `thin` 0.5 pt, `medium` 1 pt, `thick` 2 pt | `medium` 3 pt | Replace keywords with lengths: `thin` → `0.5pt`, `medium` → `1pt`, `thick` → `2pt` to keep FOP's look. Also in `border` / `border-top` ... shorthands. |
| `table-layout="fixed"` with a table wider than the sum of its columns | columns keep their widths | extra width is distributed over the columns (CSS2 17.5.2, referenced by XSL 1.1) | Usually nothing; check tables with a fixed total `width` and explicit `column-width`s. |
| Column balancing before a `span="all"` block | balanced | balanced | Nothing. |

The scanner flags templates that have no `font-size` anywhere on `fo:root` / `fo:page-sequence` / `fo:flow`, page masters
without a size, and border keywords. A template generated by XSLT may set these values in the stylesheet rather than in the
FO: check the stylesheet before adding attributes.
